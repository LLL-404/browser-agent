# BOSS 直聘求职助手 — 功能迭代改进计划

## 一、迭代范围和目标

### 1.1 迭代背景
项目已完成核心功能开发，Pylint 评分达到 9.85/10。经自我分析发现主要短板在：
- 可观测性缺失（无日志系统、无异常追踪）
- 健壮性不足（无重试机制、硬编码选择器）
- 测试覆盖率低（仅 15%）

### 1.2 迭代目标
| 目标 | 当前状态 | 目标状态 |
|------|----------|----------|
| 日志系统 | 全部使用 `print()` | 标准 `logging` 模块，支持文件输出和分级 |
| 重试机制 | 无 | 指数退避重试，关键操作失败自动重试 3 次 |
| DOM 选择器 | 散布在代码中 | 集中化管理，一处修改全局生效 |
| 测试覆盖 | ~15% | ≥ 60% |
| 并发搜索 | 无 | asyncio 并发，3 城市并行 |
| Pylint 评分 | 9.85/10 | ≥ 9.90/10 |

## 五、风险预案

| 风险 | 可能性 | 影响 | 预案 |
|------|--------|------|------|
| DOM 选择器变更导致选择器集中化失败 | 中 | 高 | 保留原有内联选择器作为 fallback |
| 并发搜索触发 BOSS 频率限制 | 中 | 高 | 信号量限流 + 失败后降级为串行 |
| logging 初始化失败导致程序崩溃 | 低 | 高 | logging 初始化失败时降级为 print |
| 重试机制导致无限循环 | 低 | 中 | 最大重试次数硬编码为 3，不可配置 |
