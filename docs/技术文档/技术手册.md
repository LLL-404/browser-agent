## 1. 系统架构设计

### 1.1 分层架构

项目采用四层架构，依赖方向严格向下：

```
┌──────────────────────────────────────────────────────────────┐
│  入口层 (agent/cli/ + agent/mcp/)                            │
│  ───────────────────────────────────                         │
│  解析用户输入（CLI 参数或 MCP 协议），分派到对应业务模式        │
│  不包含任何业务逻辑，不直接调用 Playwright                    │
├──────────────────────────────────────────────────────────────┤
│  业务插件层 (modes/zhipin/)                                   │
│  ───────────────────────────────────                         │
│  实现具体业务（BOSS直聘搜索/过滤/分析），向入口层注册工具和命令  │
│  不操作浏览器原语，不处理 Cookie/反检测细节                    │
├──────────────────────────────────────────────────────────────┤
│  通用浏览器引擎层 (agent/core/)                               │
│  ───────────────────────────────────                         │
│  封装 Playwright/Camoufox 浏览器控制、反检测、会话管理         │
│  提供与业务无关的浏览器 API，不包含任何业务词汇                │
├──────────────────────────────────────────────────────────────┤
│  共享基础设施层 (shared/)                                     │
│  ───────────────────────────────────                         │
│  配置加载、日志、重试、异常体系、指纹生成                      │
│  不依赖任何其他层，不含业务逻辑                                │
└──────────────────────────────────────────────────────────────┘
```

### 1.3 设计约束

1. **Agent 层不允许出现业务词汇**：`agent/core/` 下不得包含 "BOSS"、"zhipin"、"job" 等字符串，业务选择器通过参数注入。
2. **业务层不允许直接操作 Playwright API**：`modes/zhipin/` 必须通过 `agent/core/` 调用。
3. **依赖方向只能向下**：`shared/` → `agent/core/` → `modes/` → `agent/cli/` / `agent/mcp/`。
4. **模式注册是反向的**：入口层动态发现模式，模式通过 `get_mcp_tools()` / `register_cli()` 注册。
5. **配置只有一份来源**：所有运行时配置从 `config.yaml` 加载，通过 `get_config()` 获取。

### 1.4 数据流

```
用户输入 (CLI arg / MCP request)
    │
    ▼
agent/cli/main.py 或 agent/mcp/server.py
    │
    │ importlib/pkgutil 发现模式
    ▼
modes/zhipin/ (业务逻辑)
    │
    │ 调用 agent/core/ 浏览器 API
    ▼
agent/core/browser.py (BrowserController)
    │
    │ Camoufox / Playwright
    ▼
Chromium 浏览器实例
    │
    │ 页面交互数据
    ▼
modes/zhipin/storage.py (SQLite 持久化)
    │
    ▼
结果通过 MCP 返回 AI 编辑器 / CLI 输出
```

### 1.5 Ref 系统

为方便 AI 理解页面结构并定位元素，项目实现了 **@e1 ref 系统**：

- 调用 `get_interactive_elements()` 提取所有可交互元素
- 每个元素分配一个 ref 标识（`@e1`, `@e2`, ...）
- 包含 tag、text、placeholder、aria_label、selector 等信息
- 点击和输入时可通过 ref 引用：`click("@e1")` 自动解析为 CSS 选择器

```
@e1  [button]  "搜索"
@e2  [input]  placeholder=请输入关键词
@e3  [a]  "下一页"  aria=下一页
```

## 2. 技术栈选型说明

### 2.1 语言与运行时

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| Python | 3.11+ | 异步原生支持，丰富的浏览器自动化生态 |
| asyncio | 标准库 | 高效的异步 I/O，适合浏览器自动化场景 |

### 2.2 浏览器自动化

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| Playwright | ≥1.45.0 | 微软维护，支持 Chromium/Firefox/WebKit，API 完善 |
| Camoufox | ≥135.0.1 | C++ 引擎级反检测，基于 Firefox，比 JS 注入更彻底 |

**双引擎策略**：
```
启动浏览器
    │
    ├── Camoufox 可用？
    │   ├── 是 → 启动 Camoufox (C++ 引擎级反检测)
    │   └── 否 → 启动 Playwright + 全面 Stealth JS 注入
```

### 2.3 MCP 协议

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| mcp | ≥1.0.0 | Python 官方 MCP SDK，支持 stdio 和 SSE |

### 2.4 AI 集成

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| httpx | ≥0.27.0 | 现代异步 HTTP 客户端，支持 HTTP/2 |

### 2.5 配置与数据

| 技术 | 版本 | 选型理由 |
|------|------|----------|
| PyYAML | ≥6.0 | YAML 配置解析，人类可读 |
| aiofiles | ≥23.0 | 异步文件 I/O，不阻塞事件循环 |
| SQLite | 标准库 | 零配置嵌入式数据库，适合本地数据存储 |

### 2.6 开发工具

| 技术 | 版本 | 用途 |
|------|------|------|
| pytest | ≥8.0 | 测试框架 |
| pytest-asyncio | ≥0.24 | 异步测试支持 |
| pytest-cov | ≥5.0 | 测试覆盖率 |
| Ruff | ≥0.4.0 | 代码检查和格式化（替代 Flake8 + isort + Black） |
| MyPy | ≥1.10 | 静态类型检查 |
| pre-commit | ≥3.7 | Git 提交前钩子 |
| safety | 最新 | 依赖漏洞检查 |
| bandit | 最新 | 代码安全扫描 |

### 2.7 未选用技术

| 技术 | 原因 |
|------|------|
| Selenium | API 较 Playwright 落后，无原生异步支持 |
| Puppeteer | JavaScript 生态，与 Python 项目不匹配 |
| Scrapy | 无浏览器交互能力，无法处理 JS 渲染页面 |
| PostgreSQL/MySQL | 项目为本地工具，SQLite 更合适 |

## 4. 编码规范

### 4.1 Python 代码风格

遵循 PEP 8，由 Ruff 强制执行。关键规则：

- **行长度**: 120 字符（非默认 79）
- **引号**: 双引号（`"`）
- **缩进**: 4 空格
- **导入排序**: isort（first-party: `agent`, `chat`, `modes`, `scripts`, `shared`）
- **类型注解**: 所有函数必须标注（`disallow_untyped_defs = true`）
- **异常**: 使用 `shared/exceptions.py` 中的具体异常类型，禁止 broad `except Exception`
- **异步**: 浏览器相关操作必须使用 `async/await`

### 4.2 文件头模板

```python
"""模块简短描述。"""

from __future__ import annotations

# 标准库导入
# 第三方库导入
# 项目内部导入
```

### 4.3 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 模块 | snake_case | `browser_controller.py` |
| 类 | PascalCase | `BrowserController` |
| 函数/方法 | snake_case | `navigate_to()` |
| 私有方法 | `_` 前缀 | `_require_page()` |
| 常量 | UPPER_SNAKE_CASE | `HAS_CAMOUFOX` |
| 变量 | snake_case | `headless_mode` |

### 4.4 异常处理规范

```python
from shared.exceptions import BrowserStartError, ElementNotFoundError

# ✅ 推荐：具体异常类型 + error_code
try:
    await page.click(selector)
except PlaywrightError as e:
    raise ElementNotFoundError(
        f"元素 {selector} 未找到",
        error_code="ELEMENT_NOT_FOUND",
    ) from e

# ❌ 禁止：宽泛的 Exception
try:
    await page.click(selector)
except Exception:  # 不要这样做
    pass
```

### 4.5 类型注解

```python
# ✅ 正确：显式类型注解
async def navigate_to(self, url: str, timeout: int = 30000) -> bool:
    ...

# ✅ 正确：复杂类型使用 typing
from typing import Any
def get_config() -> dict[str, Any]:
    ...

# ✅ 正确：TYPE_CHECKING 避免循环导入
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from playwright.async_api import Page as _Page
```

### 4.6 异步编程规范

```python
# ✅ 正确：使用 asyncio 原生语法
async def main():
    controller = BrowserController()
    try:
        await controller.start()
        await controller.navigate_to("https://example.com")
    finally:
        await controller.stop()

# ✅ 正确：资源管理使用 async with 或 try/finally
async with asyncio.timeout(10):
    await browser.close()

# ❌ 禁止：在 async 函数中使用 time.sleep()
await asyncio.sleep(1)  # 正确
# time.sleep(1)          # 错误：阻塞事件循环
```

## 5. API 接口文档

### 5.1 MCP 工具接口

#### 5.1.1 浏览器控制类

##### browser_open

启动浏览器并导航到指定 URL。

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| url | string | 否 | about:blank | 导航目标 URL |
| headless | boolean | 否 | false | 是否无头模式 |

```json
// 请求
{"name": "browser_open", "arguments": {"url": "https://www.zhipin.com", "headless": false}}

// 响应
{"ok": true, "url": "https://www.zhipin.com", "title": "BOSS直聘", "engine": "camoufox"}
```

##### browser_click

点击页面元素，支持 @e1 ref 或 CSS 选择器。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| ref | string | 否 | 元素引用，如 @e1 |
| selector | string | 否 | CSS 选择器 |

```json
// 请求
{"name": "browser_click", "arguments": {"ref": "@e2"}}

// 响应
{"ok": true, "selector": "#search-btn", "step": 3}
```

##### browser_type

在输入框中输入文本。

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| selector | string | 是 | CSS 选择器或 @e1 ref |
| text | string | 是 | 要输入的文本 |
| clear | boolean | 否 | 是否先清空已有内容 |

##### browser_snapshot

获取页面结构快照。

| 参数 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| max_elements | number | 否 | 3000 | 可交互元素数上限 |
| mode | string | 否 | auto | auto/dom/accessibility |


## 6. 数据库设计与操作指南

### 6.1 SQLite 数据库

项目使用 SQLite 存储 BOSS直聘岗位数据。数据库文件位于运行目录下的 `boss_jobs.db`。

### 6.2 表结构

#### jobs 表

```sql
CREATE TABLE IF NOT EXISTS jobs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT NOT NULL,              -- 职位名称
    company TEXT NOT NULL,            -- 公司名称
    salary TEXT,                      -- 薪资范围（原始文本）
    salary_min INTEGER,               -- 最低薪资（解析后）
    salary_max INTEGER,               -- 最高薪资（解析后）
    city TEXT,                        -- 城市
    district TEXT,                    -- 区/县
    experience TEXT,                  -- 经验要求
    education TEXT,                   -- 学历要求
    benefits TEXT,                    -- 福利标签（JSON 数组）
    description TEXT,                 -- 职位描述
    company_info TEXT,                -- 公司信息
    job_url TEXT,                     -- 职位链接
    boss_name TEXT,                   -- HR 名称
    boss_title TEXT,                  -- HR 职位
    status TEXT DEFAULT 'new',        -- 状态：new/analyzed/applied/interview/offer/rejected
    score REAL,                       -- AI 评分（-1 到 1）
    analysis TEXT,                    -- AI 分析结果（JSON）
    tags TEXT,                        -- 标签（JSON 数组）
    search_keyword TEXT,              -- 搜索关键词
    created_at TEXT DEFAULT (datetime('now', 'localtime')),
    updated_at TEXT DEFAULT (datetime('now', 'localtime'))
);

CREATE INDEX IF NOT EXISTS idx_jobs_status ON jobs(status);
CREATE INDEX IF NOT EXISTS idx_jobs_city ON jobs(city);
CREATE INDEX IF NOT EXISTS idx_jobs_score ON jobs(score);
CREATE INDEX IF NOT EXISTS idx_jobs_company ON jobs(company);
CREATE UNIQUE INDEX IF NOT EXISTS idx_jobs_url ON jobs(job_url);
```

## 8. 常见问题解决方案

### 8.1 浏览器启动问题

**Q: Camoufox 启动失败**

A: 检查 Camoufox 是否已安装：

```powershell
python -c "from camoufox import AsyncCamoufox; print('OK')"
```

如未安装：

```powershell
python src/scripts/browser/download_camoufox.py
```

如仍失败，系统会自动回退到 Playwright。可以显式使用 Playwright：

```python
await ctrl.start(use_camoufox=False)
```

**Q: Playwright 浏览器未安装**

```powershell
playwright install chromium
```

**Q: 浏览器启动后立即崩溃**

检查以下几点：
- 系统内存是否充足（至少 2GB 空闲）
- 是否安装了正确的 Chromium 版本
- 查看日志输出定位具体错误

### 8.2 反爬检测问题

**Q: BOSS直聘触发验证码**

A: 尝试以下措施：
1. 确保使用 Camoufox 引擎（C++ 级反检测）
2. 增加操作间延迟（修改 `config.yaml` 中的 `runtime.delays`）
3. 减小并发城市数量（`cities_per_session: 1`）
4. 避免短时间内频繁搜索同一关键词
5. 检查代理是否被标记

**Q: 页面被重定向到 about:blank**

A: 反重定向脚本已注入，但某些站点可能有更强的对抗。检查 `ANTI_REDIRECT_SCRIPT` 是否需要更新。

### 8.3 MCP 服务器问题

**Q: AI 编辑器无法连接 MCP 服务器**

A: 检查：
1. 编辑器 MCP 配置中的路径是否正确（使用绝对路径）
2. Python 环境是否正确（`.venv/Scripts/python.exe`）
3. 服务器启动日志是否有错误

**Q: 工具调用超时**

A: 默认超时为 300 秒。如果操作确实需要更长时间，可修改 `server.py` 中的 `_TOOL_EXECUTION_TIMEOUT` 常量。

### 8.4 会话管理问题

**Q: Cookie 过期导致需要重新登录**

A: 运行 Cookie 导出工具更新：

```powershell
python src/scripts/login/export_cookies.py
```

**Q: 多个网站如何管理登录态**

A: 使用不同的 `name` 参数保存：

```python
from agent.core.session import save_cookies_to_file, load_cookies_from_file

# 分别保存
await save_cookies_to_file(boss_cookies, name="boss")
await save_cookies_to_file(qcc_cookies, name="qcc")

# 分别加载
boss_cookies = await load_cookies_from_file("boss")
qcc_cookies = await load_cookies_from_file("qcc")
```

### 8.5 数据库问题

**Q: SQLite 数据库锁定**

A: 确保同一时间只有一个进程在写入。检查是否有残留的浏览器进程。

**Q: 数据库文件损坏**

```powershell
# 备份后重建
Copy-Item boss_jobs.db boss_jobs.db.bak
Remove-Item boss_jobs.db
# 重新运行程序会自动创建新数据库
```

### 8.6 性能问题

**Q: 浏览器操作很慢**

A:
1. 使用 `headless=True` 模式
2. 减少截图频率
3. 检查网络延迟
4. 使用 `profiler` 模块定位瓶颈：

```python
from shared.profiler import get_hot_functions, generate_report
print(generate_report())
```

**Q: 内存占用过高**

A:
1. 定期调用 `cleanup_old_profiles(max_age_days=3)` 清理旧 Profile
2. 在任务完成后调用 `ctrl.stop()` 释放浏览器资源
3. 控制并发任务数量
