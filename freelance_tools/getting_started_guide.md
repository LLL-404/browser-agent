## 📅 第三天及以后：接单实战

### 3.1 如何响应客户咨询

#### 收到咨询后的黄金10分钟内：

```
✅ 第1步：快速响应（<5分钟）
"您好！已看到您的需求，正在评估可行性，
稍等片刻给您详细回复~"

✅ 第2步：分析需求（5-10分钟）
• 能不能做？（技术上是否可行）
• 要多久？（工期预估）
• 多少钱？（报价计算）
• 有没有风险？（反爬、法律等）

✅ 第3步：专业回复
使用 service_copywriting.md 中的【沟通话术模板】
```

#### 需求评估清单：
```
技术可行性检查：
□ 目标网站能否正常访问？
□ 数据是否在HTML中（还是JS动态渲染）？
□ 是否需要登录/验证码？
□ 数据量大概多少？

商业可行性检查：
□ 客户预算是否合理？（低于市场价2倍以上的要警惕）
□ 工期是否合理？（太急的项目容易扯皮）
□ 需求是否清晰？（模糊需求必须先细化）

风险评估：
□ 是否涉及用户隐私？
□ 是否违反目标网站ToS？
□ 是否涉及灰色地带？
→ 以上任何一项有疑问，直接拒绝！
```

## 💰 收费策略详解

### 4.1 报价公式（必背）

```python
def calculate_quote(difficulty_hours, rush_factor=1.0):
    """
    计算项目报价
    
    Args:
        difficulty_hours: 技术难度工时（纯编码时间）
        rush_factor: 加急系数（普通1.0，加急1.5-2.0）
    
    Returns:
        推荐报价（元）
    """
    base_hourly_rate = 50  # 新手时薪（后续可涨到80-150）
    
    # 总工时 = 编码时间 × 2（留出调试+沟通余量）
    total_hours = difficulty_hours * 2
    
    # 基础报价
    base_price = total_hours * base_hourly_rate
    
    # 加急溢价
    final_price = base_price * rush_factor
    
    # 取整到百位数（显得更专业）
    return round(final_price / 100) * 100


# 使用示例
print(calculate_quote(8))      # 普通：1600元
print(calculate_quote(8, 1.5)) # 加急：2400元
```

## ⚠️ 常见问题与解决方案

### Q1：客户要求先做完再给钱怎么办？
**答案：坚决不干！**
```
话术：
"理解您的顾虑。但我这边也有成本投入（时间+精力），
行业惯例是收30-50%启动定金。
这样双方都有保障：
• 您付了定心钱，我会优先安排
• 我收到了启动资金，全心投入

要不我们先用小额定金（比如总金额的30%）启动，
您看到初步成果后再付尾款？"
```

### Q2：客户一直加需求怎么办？
**答案：提前约定修改次数**
```
合同/聊天中明确写入：
"报价包含3次免费小修改（调整格式、修复bug等）
超出部分：50元/次 或 重新评估报价"

遇到客户加需求：
"这个功能不在原需求范围内哦~
属于新增需求，需要额外XX元/XX时间
您看是加预算还是放到下一期做？"
```

### Q3：技术实现不了怎么办？
**答案：诚实沟通 + 给替代方案**
```
话术：
"感谢信任！我仔细评估了这个需求，

坦率说：【具体难点】导致风险较高，
强行做可能会出现【可能的后果】

我的建议是两个方案：
方案A：简化版（去掉难点），费用XX元，成功率99%
方案B：完整版，但需要额外XX时间和XX费用，且不保证100%

您觉得哪个更合适？"
```

### Q4：被客户差评/投诉怎么办？
**答案：冷静处理 + 平台申诉**

```
第一步：私下联系客户
"看到您的评价了，非常抱歉没达到预期。
请问具体哪里不满意？我可以免费修改到您满意为止"

第二步：如果客户不理睬
收集证据（聊天记录、交付物、需求文档）
向平台提交申诉，说明情况

第三步：吸取教训
• 哪里没做好？
• 下次如何避免？
• 更新自己的接单 checklist
```
